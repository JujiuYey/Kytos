# 角色共创结构化草稿共识

状态：已达成方向共识，待继续细化字段与交互流程。

## 背景

当前角色结构化草稿以姓名、核心概念、性格、动机、背景、人际关系和说话方式为主。这些字段适合描述文学人物，却不能直接定义一个可以被稳定复现的视觉角色。

当这些抽象信息被直接用于生图时，模型需要自行推断人物的长相、体态、服装、配色和表现方式。每次推断都可能得到不同答案，导致同一角色在不同图片中的形象和画面风格发生漂移。

独立画风系统是在上游角色定义不足后增加的补偿层。它只能约束绘制方式，无法补齐角色身份和外形锚点，也无法从根本上解决一致性问题。

## 核心共识

### 1. 废弃独立画风系统

不再把画风作为脱离角色共创的独立管理和选择系统，也暂不考虑画风展示页面及其相关产品流程。

用户在讨论人物形象时，通常已经同时形成了对人物长相和呈现方式的设想。因此，人物的视觉表现规则应在角色共创过程中一并确定。

数据结构上仍需区分：

- 角色形象：这个人长什么样。
- 视觉表现：这个人以什么绘制方式呈现。
- 场景内容：这个人这一次在哪里、做什么。

三者在同一次共创中完成，但承担不同职责，不能互相替代。

### 2. 重做角色结构化草稿

角色共创不再以“补齐文学人物资料”为完成标准，而应形成一份能够让角色在不同场景中稳定复现的视觉角色定义。

新的结构化草稿分为三组：

1. 人物种子
2. 形象锚点
3. 视觉表现

### 3. 抽象叙事字段不再直接进入生图提示词

性格、动机、背景、人际关系和说话方式可以作为聊天、故事和表演设计的创作上下文，但不能再被原样拼接到生图提示词中，让图像模型自行解释。

需要用于生图的信息，必须先被转化为可观察、可描绘的视觉事实或行为表现。例如：

- “疲惫但不轻易放弃”不能直接决定长相。
- 应转化为“半睁眼、轻微黑眼圈、肩膀略微内收；疲惫时停顿和发呆，不做夸张崩溃动作”。

### 4. 抽卡属于角色共创，不属于资产管理

角色形象尚未确定时，用户可以在共创对话中抽取视觉方案，用候选图和结构化描述探索人物形象。

抽卡产生的是可讨论、可否定、可组合的视觉假设。只有经过用户确认的内容，才能进入正式结构化草稿，成为后续生图的角色约束。

角色视觉资产管理暂时不调整。它负责管理已经产生的图片，不承担角色定义和视觉探索职责。

## 结构化草稿

### 一、人物种子

人物种子只保留开始视觉探索所需的最少上下文，不承担文学人物档案的职责，也不直接原样发送给图像模型。

| 字段     | 作用                                         |
| -------- | -------------------------------------------- |
| 姓名     | 标识当前角色                                 |
| 人物种子 | 用一句话说明人物大概是谁，为视觉探索提供起点 |

性格、动机、背景、关系、说话方式、行为矛盾、日常处境和叙事备注不进入角色结构化草稿。故事创作需要这些信息时，应在故事流程中根据具体作品另行讨论。

### 二、形象锚点

形象锚点负责保证不同图片中的人物仍然是同一个人。

| 字段       | 作用                                         |
| ---------- | -------------------------------------------- |
| 视觉总述   | 用一段具体描述概括人物最容易被识别的视觉组合 |
| 年龄与体态 | 定义年龄感、身高感、体型、比例和整体姿态     |
| 脸部锚点   | 定义脸型、眼睛、眉毛、嘴型等稳定识别特征     |
| 发型锚点   | 定义发型、发色、长度、轮廓和稳定细节         |
| 默认服装   | 定义角色最常用、最具识别度的基础造型         |
| 角色配色   | 定义属于角色身份的固有颜色关系               |
| 标志物     | 定义耳机、眼镜、杯子、伤疤等识别物件         |
| 轮廓识别点 | 定义缩小或剪影状态下仍能认出角色的特征组合   |

字段的目标不是堆砌五官参数，而是形成一组稳定的组合识别特征。

### 三、视觉表现

视觉表现记录用户在共创人物形象时确认的绘制规则，取代独立画风系统。

| 字段       | 作用                                         |
| ---------- | -------------------------------------------- |
| 表现形式   | 线稿、赛璐璐、厚涂、像素或其他主要形式       |
| 线条与造型 | 线条粗细、整洁程度、造型简化和夸张方式       |
| 色彩规则   | 全彩、有限色、黑白或强调色的使用方式         |
| 细节密度   | 控制人物、服装和环境的细节程度               |
| 背景规则   | 纯色、留白、少量环境线条或完整场景的处理方式 |
| 文字规则   | 是否允许手写文字、注释、漫画符号等视觉元素   |
| 排除项     | 用户明确不希望出现的形象或画面特征           |

视觉表现描述的是该角色及其内容的稳定视觉语言，而不是一个可随意套用到任意人物上的画风标签。

“必须保持”不作为独立字段：已经确认的形象锚点默认必须保持。“允许变化”由每次具体创作的场景要求决定。参考形象应由系统直接绑定图片，不要求用户再填写文字说明。

## 示例：阿九

### 人物种子

- 人物种子：一个长期熬夜、擅长解释技术问题的年轻程序员。

### 形象锚点

- 视觉总述：红色短乱发、黑色包耳耳机、半睁下垂眼、瘦长略含胸、宽松白色连帽衫，通常拿着红白咖啡杯。
- 脸部锚点：细眉、下垂的半睁眼、轻微黑眼圈、克制的嘴型，表情通常介于走神和无奈之间。
- 身体锚点：窄肩、偏瘦、四肢修长，站姿松散，动作幅度较小。
- 标志物：黑色包耳耳机、红白咖啡杯。

### 视觉表现

- 松散的黑色手绘线稿，人物造型适度简化。
- 画面保留大面积白色，仅头发、杯子和提示信息使用红色。
- 背景通常用少量线条表达，不进行完整铺色和写实光影塑造。
- 允许少量手写中文标注和漫画式提示符号。
- 排除项：写实厚涂、复杂光影、完整暖色环境铺色、精致商业插画质感、肌肉体型和成熟硬朗面容。

## 数据使用边界

后续生成图片时，不应再把整份角色档案无差别发送给图像模型。

| 数据                                       | 是否直接用于生图                             |
| ------------------------------------------ | -------------------------------------------- |
| 人物种子                                   | 仅在当前画面确实需要身份上下文时提供简化信息 |
| 性格、动机、背景、关系、说话方式等叙事资料 | 不进入角色结构化草稿，也不直接用于生图       |
| 形象锚点                                   | 是，作为角色身份约束                         |
| 视觉表现                                   | 是，作为稳定呈现规则                         |
| 当前场景要求                               | 是，只描述本次图片需要发生的内容             |

## 角色共创流程

角色共创不要求用户按照结构化字段逐项填写表单。系统通过自然对话理解用户已经确定的内容、仍然模糊的部分和明确排除的方向，并持续维护一份逐步成形的角色草稿。

### 草稿状态

结构化草稿中的内容分为三种状态：

| 状态   | 含义                                           |
| ------ | ---------------------------------------------- |
| 待探索 | 用户尚未形成明确想法，可以通过讨论或抽卡探索   |
| 暂定   | 当前方向可用，但用户尚未将其确认为稳定角色锚点 |
| 已确认 | 已成为角色正式设定，后续探索和生图不得随意改变 |

草稿不是一次生成后保持不变的总结，而是角色共创过程中持续演化的工作对象。

### 第一次抽卡前的最小信息

第一次抽卡的目的不是生成最终定妆照，而是帮助用户发现一个值得继续发展的完整角色方向。因此，用户不需要先回答年龄、体型、脸型、发型和服装等全部问题。

第一次抽卡前只需要形成一个最小角色种子：

| 信息     | 作用                                                 |
| -------- | ---------------------------------------------------- |
| 人物种子 | 用自然语言说明人物大概是谁                           |
| 必须保留 | 记录用户已经明确想到、不能被抽卡改变的特征           |
| 明确排除 | 记录用户确定不想出现的形象和表现方向                 |
| 视觉倾向 | 记录用户已经形成的绘制与呈现偏好；没有时可以继续探索 |

示例：

```text
人物种子：
一个长期熬夜、擅长解释技术问题的年轻程序员。

必须保留：
年轻、疲惫感、随身带咖啡。

明确排除：
精英商务感、成熟硬朗、赛博朋克。

视觉倾向：
希望简单、轻松，不要精致厚重。
```

这些信息可以由用户主动描述，也可以由系统从前面的自然对话中提炼，不应要求用户重复填写。

### 抽卡前确认

抽卡属于付费生图操作，必须由用户明确触发。生成前，系统需要先用简短语言说明本次会保持什么、排除什么、探索什么。

例如：

> 我会保留“年轻、疲惫、咖啡”这三个锚点，避开商务精英和赛博朋克，接下来探索人物的体态、脸部、发型、服装及具体表现方式。

确认的目的不是让用户审核完整提示词，而是确保系统没有误解角色种子和本次探索边界。

### 抽卡方式

抽卡不应分别生成互不相关的发型卡、五官卡和服装卡。人物形象依赖多个特征之间的整体协调，因此每张卡都应是一套内部一致的完整形象方向。

每个方向可以同时探索：

- 体型与人物轮廓
- 脸部与发型组合
- 默认服装和标志物
- 角色固有配色
- 线条、色彩和背景等视觉表现规则

已经进入“已确认”状态的内容不能在后续抽卡中被重新随机。需要继续探索时，只开放用户指定或仍处于“待探索”“暂定”状态的变量。

### 抽卡输出

每张角色卡不能只有一张图片，还需要附带一份简短的方向说明，让用户明确自己选择的是怎样的角色定义。

示例：

```text
方向 A：松散技术宅

形象组合：
瘦长体型、短乱发、半睁眼、宽松连帽衫、包耳耳机。

视觉表现：
黑色松散线稿、单一强调色、大面积留白。

识别重点：
头发轮廓、耳机、含胸姿态和咖啡杯。
```

用户选择的不是一张孤立的好看图片，而是一套可以继续发展的角色方向。图片用于直观判断，文字用于把被选择的形象锚点和视觉规则写回结构化草稿。

用户选中一个方向后：

1. 选中的形象组合和视觉规则进入暂定草稿。
2. 用户可以通过对话修改其中的具体部分。
3. 需要重新探索时，只改变开放变量，保留其他锚点。
4. 用户确认后的内容进入正式角色设定。
5. 被确认的图片成为后续生成可使用的参考形象。

## 当前范围

本阶段只确认产品方向和结构化草稿的基本组成，暂不进入以下工作：

- 不修改现有代码和存储结构。
- 不设计最终页面布局和交互细节。
- 不调整角色视觉资产管理。
- 不讨论旧画风数据的迁移和兼容方式。
- 不确定最终字段类型、必填项和生成提示词格式。
- 不确定抽卡数量、卡片版式和最终页面布局。

下一阶段继续讨论候选方向如何修改、合并和确认，以及满足哪些条件时可以认为角色共创已经完成。
